# Delivery policy workspace

GET `/admin/policies/delivery/current` returns evaluatedAt, current, nextScheduled, latest, bounded history and availability `{checkoutEnabled, deliveryEnabled}`. Current and next are selected across all versions by effective time and descending version independently of the latest 100 history entries. Availability uses the existing public fulfillment calculation at the same evaluation time and within the same repeatable database snapshot. Approval status alone is not a checkout-readiness promise.

Super Admin/MFA, a current actor/session check, private/no-store responses and an atomic minimal DELIVERY_POLICY_CURRENT READ audit protect the endpoint. DELIVERY publication now rechecks the current actor/session before the existing expected-version lock, immutable Q1 policy creation and CREATE audit. No schema/migration is required. Existing financial/fulfillment calculations and order snapshots are unchanged.

The existing typed settings remain authoritative: complete list of 1–100 zones; unique stable lowercase alphanumeric/hyphen references; plain-text area label 2–160 and city/state 2–120 characters; nonnegative integer-string feeKobo up to 15 digits; fixed collection availability and approved workshop address. Source/evidence/effective-time checks are unchanged. The dashboard uses exact string/BigInt NGN conversion, supports zero and makes list replacement explicit.

The owner can provide approved areas/fees and schedule their effective time in the dashboard. Draft row structure, values and zone identities persist with their original policy base. Exact nested Q1/actor/settings receipts and current-state preflight protect approval; uncertain responses require independent reconciliation and are never automatically replayed. No claim of durable original-request lookup is made; that remains ADM-63 follow-up work.
