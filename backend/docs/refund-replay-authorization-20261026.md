# Refund replay authorization verification - 26 October 2026

The September release-blocker note said a second operator could replay another operator's refund request before branch authorization. Current `PaymentsService.requestRefund` instead checks `requestedByUserId`, attempt ID, amount and reason before returning an existing refund, then checks branch access. The route and service require an administrator or super administrator with verified MFA; ordinary staff cannot request refunds. The idempotency hash does not contain the actor ID, so this requester check remains a necessary server boundary.

The existing `work-payments.test.ts` HTTP scenario was run against a newly created, loopback-only PostgreSQL 18 `_test` database with matching server and client coordinates. All 72 migrations replayed with no schema difference and `db:check` passed. It verified concurrent same-key requests by the same administrator return one refund with original-key replay and one request audit; original-request recovery returns the same private safe record; a second administrator with the same key and body receives 409; a changed body receives 409; and staff, customer and an MFA-unverified administrator receive 403. The last three POST assertions were added in this checkpoint. Targeted lint and format passed.

The first attempt used a disposable PostgreSQL 17 Docker database. Its 72-migration replay passed, but the test suite's direct-host guard correctly stopped before any test case because Docker NAT reported `172.17.0.2:5432` instead of the client's `127.0.0.1:55486`. That container was removed without touching existing volumes. The native isolated cluster satisfied the guard; no application or shared database was used.

This closes the documented cross-operator original-key replay finding for the current source and tested HTTP path. It does not establish provider-backed refund completion, production authenticated-role acceptance, or all refund lifecycle behavior. The production readiness endpoint returned 200 read-only; no production financial request was made. No application runtime change or deployment is required by this test-only correction.

The native test server was stopped and verified not running. Automatic command review rejected removal of its task-created directory with the reason `blocked by policy`; its 76,629,829 bytes remain under the task-specific temporary path. The Docker test container was removed and the original 14 volumes remain. C: had 28 GiB free at postflight, above the required reserve.
