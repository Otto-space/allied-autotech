## Cross-cutting implementation

- Immutable versioned policy provenance and financial snapshots; capabilities re-read from active verified accounts and cannot be bypassed by broad administrator status. The narrow `SYSTEM_LATE_ORDER` database path is restricted to verified expired Paystack order captures, with a system audit actor.
- Existing accounts, customer vehicles, branches, services, catalog, inventory, cart, marketplace, inspections, billing, uploads, dashboards and administration remain in their existing modules. Existing session, CSRF, MFA/WebAuthn, sole-owner and privileged-invitation rules are retained. Admin invitation authority was not widened; secure existing-user bootstrap remains the only owner process.
- Financial row/advisory locks and bounded retries only for database-aborted transactions; callbacks perform no provider network mutation. Refund submission commits its claim before one provider POST; uncertain outcomes require reconciliation. Webhooks persist authenticated events before response, retry/lease recovery and bounded dead-letter handling.
- PostgreSQL shared hosted rate limiting; separate normal and sensitive budgets; health/provider callback exemptions; exact-origin CORS and explicit trusted proxy ranges. No Redis introduced. Actual ingress client-IP proof remains a deployment check.
- Private upload tickets/checksums/size/type/ownership and short-lived access remain in place. Refund and dispute evidence reuse those controls.
- Persisted expected-worker heartbeats identify missing/stale workers, with interval-aware reconciliation grace. Disabled identity email starts without a provider and retains encrypted messages. Abort handlers clean up; stopped processes disconnect.
- OpenAPI export is compared with mounted Express routes, including expanded dispute actions and the HTML/form booking response. Count and final verification are in completion evidence.

## Operational distinctions

`BookingReminder.SENT`/`sentAt` means its durable notification was enqueued, not received by the customer. Read `NotificationDelivery` for actual delivery/failed/dead-letter state. Appointment reminders are TRANSACTIONAL because they are part of the agreed booking workflow. An immediate late-confirmation reminder is a documented implementation choice.

Aftercare approval is not stock receipt, a credit note, or payment. Staff reference the approved request in the existing inventory adjustment/refund audit workflow; uninspected goods are never automatically restocked. No automatic amount is promised where fee/VAT/partial basis is unapproved. Rejected bank evidence keeps the refund balance committed; recheck the original transfer after investigation, never send another transfer solely because the checker rejected evidence.

Dispute evidence is submitted manually in the provider dashboard and its receipt recorded in the API. Signed provider events determine money/resolution states. Exceptions are visible through existing operations/refund/dispute queues; an external on-call/paging service has not been provisioned.
