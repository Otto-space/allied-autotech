# Reviewed cart clear: cross-tab safeguard

The customer cart previously read the reviewed contents again just before `DELETE /customers/cart`, but the server accepted an empty body and deleted every item. A second tab could change an item after that read and before deletion. The customer's confirmation would then remove contents they had not reviewed.

The DELETE now requires `expectedItems` containing the item ID, product ID, quantity and unit price in the order returned by `GET /customers/cart`. The server locks the owned cart row, reads its current items, compares the snapshot and deletes only if they match. A changed cart returns 409 and preserves its items. Item updates and removals acquire the same cart lock; checkout already locks it. The client retains its full preflight comparison and sends the reviewed snapshot. The backend rejects old empty-body requests with 422, closing the unguarded path. No schema, migration, payment or stock-reservation rule changed. The public site remains in browse/enquiries mode.
