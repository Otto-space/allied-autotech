# Managed workforce bookings — milestone 106

Status: locally accepted on 19 October 2026. Route `/admin/workforce/bookings`. The full application goal remains active.

## Outcome

The dedicated workspace replaces sparse generic cards with a six-column appointment table and labeled mobile records. Service, customer name/phone, vehicle/registration, branch, Lagos schedule and readable booking status appear together. Missing vehicles have an explicit fallback. An ordered Overview / Bookings breadcrumb uses the existing chevron icon.

Search and all eight booking states apply together across the server-authorized scope. Filters and First/Previous/Next history persist in the URL through reload and browser Back. Background refresh preserves unsent search text. Clear resets an unsent draft even on an already unfiltered URL. Loading, errors, malformed responses and scope changes hide retained customer information; empty scope and unmatched filters have distinct guidance.

The page is read-only. No unsupported detail, legacy administration, technical job, assignment or payment action is introduced. See the [backend contract and preservation evidence](../../../backend/docs/workforce-bookings-workspace.md).

## Design and comparison

Native baselines at 430/768/1280/1440px preceded implementation. Fresh complete desktop/mobile concepts and the [locked specification](workforce-bookings-oct-concepts/spec.md) establish hierarchy, controls, table/record layout and states. Both local concept images and all four final captures were viewed.

The implementation retains the actual logo, role-aware navigation and two-row mobile header. Quicksand headings are 28px desktop/24px mobile, table and field text 14px, supporting text 13px. Visible input borders, red focus outlines, 44px controls, restrained cool surfaces and one continuous results panel follow the concept. Desktop filters align horizontally; tablet filters use two columns and mobile filters stack. The mobile refresh/time stack and footer inside the results panel are the documented concept corrections. Generated branding, sample counts and inconsistent status colors are replaced by actual application branding, response counts and a consistent semantic palette.

Native review found no horizontal overflow, overlapping controls, clipped content or framework overlay at the four capture widths. The 320px long-content check covers service, customer name/phone, branch and registration. Desktop date text wraps within its column; mobile records preserve complete labeled values.
