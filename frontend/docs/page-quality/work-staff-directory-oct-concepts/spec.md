# Staff directory — implementation specification

Use the existing Allied shell, Quicksand and compact breadcrumb. Desktop heading30px/mobile24px, body14px, 48px bordered controls and16px mobile control text. Header holds staff identity guidance and the existing promotions/invitations navigation. A compact search form searches name or email on explicit submit; role/status/branch selects retain their actual contract. Clear filters and refresh are secondary. Preserve inactive and unassigned branch facts.

Desktop uses compact ruled records: person/email/job title, account role, account status, branch, verified email and View account. Tablet/mobile reflow to named identity plus paired labelled facts and a clear detail link, without horizontal scrolling or hiding important data. Show loaded-page count only; no guessed workforce totals. Use neutral self/protected labels, not invented permission claims. Existing breadcrumbs remain route-aware; no raw identifiers in visual labels.

URL owns search, role/status/branch and bounded cursor trail. Reload/Back/Forward restore them. Data parser verifies ordering, identity, filters, branch relation and page cursor. Distinguish initial loading, temporary refresh failure, empty, malformed and denied states. Prevent stale paging, retain labelled stale facts only for recoverable errors and clear all records/links on access loss. Role-specific access and supported filters/search/paging are verified through browser, API and isolated connected read-only flows. Detailed account controls and invitations are separate subsequent gates.
