# Customer garage concepts

Prepared 9 October 2026 before production edits to `/dashboard/vehicles`. The baseline was inspected at 390, 768, 1280 and 1440px. Built-in ImageGen produced the [desktop list](desktop.webp), [mobile list/form](mobile.webp) and [desktop form/recovery states](states.webp). PNG originals remain in Codex storage; WebP files change encoding only.

## Design specification

- Preserve the actual role-aware shell and official Allied logo. Semantic Overview / My vehicles breadcrumb. Quicksand throughout: 30/27px page title, 18px vehicle/guidance headings, 22px dialog title, 13-14px body/labels, 12px metadata; inputs16px. Ink #01121A, red #E60301, white, canvas #f4f6f8, border #cbd5df, input border #82939f. Controls6px / containers8px radius, inputs48px, actions44px minimum.
- Keep title **Your vehicles** and subtitle **Keep the details you use for workshop visits in your account.** Header actions outlined **Refresh**, red **Add a vehicle** with plus. Ink guidance band: CarFront outline, **Ready for your next workshop visit**, **Keep your vehicle details up to date. Add photos from Manage photos.**
- Toolbar: current-page vehicle count and Rows per page 10/20/50, default20. API has only limit/cursor: no search, sorting or global total. Persist validated pagination in the URL and exclude UI-only history from API requests.
- Continuous white records with thin separators. Small44px car icon, year/make/model heading. Registration, Colour, Mileage, VIN are real API fields; null says Not provided, zero mileage is 0 km. Desktop four metadata columns and right-side action rail: camera Manage photos, pencil Edit details, trash Remove. Narrow/tablet layouts use two metadata columns with full-width VIN and actions below. All records remain expanded; no stock photos, fabricated status or per-row photo requests.
- Page-local Previous / Page N / Next; direct cursor links use Later page / First page. Footer Need help with your vehicle? Contact support. Exact existing photo-detail link; the detail route retains its own future gate.
- Native modal form opens from Add or Edit, white width660px with viewport-contained scrollable body and fixed action footer. Heading Add a vehicle or Edit your vehicle, X close; existing introductory copy. Vehicle details has required Make/Model (80 characters), Year (integer1886 through next UTC year). Additional details retains existing description and optional Registration, Colour, VIN and Mileage. Make/model and registration/colour share desktop rows; mobile stacks. Text fields remain free text; no catalogue taxonomy is available for personal garage records.
- Backend-aligned trimming, control-character exclusion, registration/VIN capitalization and validation, integer mileage0..5000000. Field-specific errors, error summary/focus, preserved safe drafts and typed API submission. Explicit Cancel and Save vehicle. Disable concurrent submissions; prevent closing during the request. On unconfirmed outcomes, do not automatically retry and require closing/re-reading records before another attempt. Reject incorrect mutation-response identities rather than reporting success.
- Removal is an explicit confirmation: **Remove this vehicle?**, year/make/model plus **will be removed from your account, including its saved photos. Bookings stay in your account.** Show registration. **Keep vehicle** (initial focus) / **Confirm removal**. Existing backend deletes attached media and retains bookings via nullable vehicle relation. Escape/cancel restore focus, modal locks background scrolling, keyboard focus stays contained. Short viewports scroll the body while retaining actions.
- Initial empty: **Your garage is empty**, **Add a vehicle to keep its workshop details in one place.**, **Add your first vehicle**. Later-page empty: no vehicles on this page with First page. Manual read failures hide old rows with Retry vehicles; background failures show an explicit stale notice. Loading skeletons match record anatomy. Session changes clear private records, dialogs and late mutation feedback.

## Intentional artwork corrections

Use the real shell/logo and outline CarFront/Lucide icons, not the mobile artwork's substituted logo, phone chrome or filled car icons. Keep all rows expanded instead of the mobile artwork's invented collapsed secondary records; use actual API identities. Use actual text inputs instead of the state artwork's invented make/model/year dropdown arrows. Missing records and skeletons never imply real vehicle imagery. Fixed application support controls stay outside the top-layer dialog. Financial, booking and media detail workflows are not redesigned here.
