# Customer Care — scoped security verification

Date: 7 October 2026. Scope: public `/contact`, its shared submission/review components, account shortcut, Maps frame policy and the existing public support API. This is a source review and local acceptance record, not a whole-application penetration test or staging certification.

The review found one Maps configuration defect, corrected below. No new mandatory backend endpoint or confirmed high/critical vulnerability was established within this scope. Existing public origin checks, bounded input schemas, rate limits and customer authorization remain intact.

## Corrected finding

**CC-01 — Low; configured Maps unavailable under the page policy.** The previous CSP omitted an external frame destination, so `default-src 'self'` would block the Google Maps iframe rendered by Contact when a key was configured. This was a functionality/configuration defect, not evidence of an authorization bypass.

Correction: [proxy.ts](../../proxy.ts), lines 27 and 34–38, permits only `https://www.google.com/maps/embed/` in `frame-src` for exact pathname `/contact` when its public Maps key is nonblank. Other routes and unconfigured Contact retain self-only frames. Nonced scripts, `object-src 'none'`, `frame-ancestors 'none'` and private-route cache headers are retained. Seven [policy tests](../../tests/unit/contact-map-policy.test.ts) cover missing/blank configuration, the configured Contact path and four unrelated/private paths. A real keyed iframe remains unverified because the owner has no key yet.

## Evidence and limits

Local evidence under `C:/Users/PC/.codex/`: `contact-oct-security-final.log`, `contact-oct-real-final.log`, `contact-oct-map-policy.log`, `contact-oct-backend-security.log` and the browser evidence in the [expanded page report](contact-expanded.md). The existing backend notification/security test file passed six tests, including escaping untrusted notification content; it is not represented as full endpoint security coverage.

The first real-browser run stopped on a screenshot timeout after a submission; the subsequent completed acceptance run used a new synthetic QA identity and separately verified both writes and audit records. The database was checked as `allied_vehicles_qa` on isolated PostgreSQL port 55439 before writes. External delivery providers were disabled; receipt/persistence does not prove email delivery.

Remaining deployment checks: actual notification delivery, production proxy/rate-limit configuration, runtime headers at the deployed edge, and a correctly restricted Maps browser key. The existing address fallback works without Maps configuration. No live customer records, credentials or external messages were used. There is no claim that source inspection alone establishes complete application security.
