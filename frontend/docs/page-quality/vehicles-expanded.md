Route: `/vehicles`. Date: 7 October 2026. Status: expanded local gate complete. This report supplements the [September acceptance record](vehicles.md), whose query and pagination contract remains applicable. It does not certify vehicle detail, transactional forms, other routes or deployment.

## Audit and scope

The preceding Home milestone passed before this page began. Fresh baseline captures at 390, 768, 1280 and 1440px used the production preview with the isolated real API. They showed a working URL-based search/filter system, but relatively large display type, a flat inventory surface, generic package-image fallbacks, sparse card information and no buying-process explanation.

Source review covered the server seed loader, catalogue component, query normalizer, filter drawer, listing schema, public vehicle query schema/repository and existing detail actions. The page uses anonymous `GET /public/vehicles` with a 12-item limit and backend-provided images. No new endpoint, data model, permission, mutation or dependency was needed. `conditionReports` is a real public projection; its presence supports only the statement that a report is available. There is no complete make/model options dataset or global total. The exact-name fields and current-page count remain truthful fallbacks; optional metadata work remains [API-01](../../../BACKEND_IMPLEMENTATION_GAPS.md).

Three [coordinated concepts](vehicles-oct-concepts/README.md) were generated before coding. The existing shell, genuine font, approved editorial images and working filters govern the specific deviations documented there.

## Implementation

- Compact hero; cool-grey marketplace canvas; raised white search panel; Login-derived field focus and readable borders.
- Body-type shortcuts use the existing query updater. They preserve other filters and sorting, reset the cursor/trail, respect Back/Forward, and display a selected type outside the common shortcuts. All types removes only the body-type filter.
- Cards show the API title, make/model/trim, year, condition, exact formatted price, mileage, transmission, fuel and city/state. Zero mileage and zero-priced fixture values remain distinct from missing values. Missing specifications explicitly say “Not listed.” Real production price validation is unchanged.
- Whole-card detail links retain one keyboard stop per card and a visible View vehicle cue. Published condition reports produce an informational indicator; absent reports produce no invented badge. Account mutations remain on the separate detail route.
- Safe media chooses the primary image or first image and remounts on URL change, so a failed earlier URL does not prevent recovery. Real vehicle photographs are contained; unavailable media uses a compact CarFront fallback.
- Open three-step buying guidance explains comparison, customer inspection/enquiry requests and appointment confirmation. Existing lifestyle discovery and contact paths remain below it.
- Card hover movement is limited to pointer devices without reduced-motion preference. Focus rings stay inside clipped card edges. Loading skeletons include the richer card content height; Retry is disabled while its request is active.

Production changes are confined to [page.tsx](../../app/vehicles/page.tsx), [vehicle-catalogue.tsx](../../app/components/vehicle-catalogue.tsx) and [vehicles.css](../../app/vehicles/vehicles.css). Existing filter/debounce/history logic, server/client separation and shared public components are retained.

## API-01 discovery extension — 9 October 2026

This acceptance supersedes the earlier exact-name-only/current-page-count limitation. `/vehicles` now uses additive `GET /public/vehicles/discovery` and `/public/vehicles/facets`. The original public listing/detail routes remain supported. Make/model suggestions are searched and paged on the server; model options require the selected make. Manual full-name entry and Retry remain available when suggestions fail. The heading separates exact filtered matches from the current page count. Empty or invalid later pages offer a return to the first page while retaining filters.

Results, options and totals use AVAILABLE listings at active branches. No VIN, acquisition or customer fields are added. Signed cursors bind filters/sort/endpoint and retain their position after anchor deletion; old UUID links require a currently matching visible anchor. Page/count share one repeatable-read snapshot. Separate requests may reflect changed inventory, prices or years. Limits default to 20 and cap at 50; the frontend requests 12 vehicles and 20 options. Option searches are literal case-insensitive prefixes; exact-name filters treat percent/underscore literally. URL history is bounded and never forwarded as an API filter.
