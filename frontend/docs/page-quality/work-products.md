# Administrator product catalogue — local acceptance

Route `/admin/products`, Admin and Super Admin. Gate 56 accepted locally on 13 October 2026. The accepted frontend count is 56. The whole-application goal and deployed acceptance remain open.

## Implementation and contracts

Four fresh [desktop, mobile, editor and state concepts](work-products-oct-concepts/spec.md) preceded implementation. The generic resource page has been replaced with a dedicated catalogue: URL-backed search, category, visibility, featured, sort and optional brand/make/model/year filters; an ink results band with the actual page count; complete product, price, availability and visibility records; and reachable edit/media actions. Mobile records stack with labels. Paging survives reload and browser history. It remains live cursor pagination, not a database snapshot or exact total. Cursor history is bounded; a direct or sufficiently deep cursor displays “More results” rather than inventing a page number.

Creation, editing and media management are separate URL-backed views within the catalogue. The editor groups all eleven fields into details, pricing and visibility, with a guidance rail and working inventory link. Money stays in integer-kobo strings, including values above JavaScript's safe integer range. Category choices are paged; selection and labels survive page changes and draft restoration. An unresolved restored category cannot be reviewed under another category's name. A failed category read has a working retry control.

Every save presents all eleven facts. Cancellation writes nothing and returns focus to the review trigger. A direct administrator read supplies the current product independently of list paging, and every existing-product edit sends `expectedUpdatedAt`. Pre-save and server checks reject stale reviews. Returned saved products must match the reviewed identity and values before success is shown. Temporary read failures preserve drafts and block writes; denied/missing reads remove private fields, mismatched identities are hidden, and malformed responses cannot enable a save.

Owner-scoped pending markers survive reload. Interrupted edits require an explicit fresh read and draft replacement. Interrupted creation requires manual catalogue reconciliation before starting a blank draft; no automatic POST replay or durable creation receipt is claimed. Media uses the same direct read, existing binary upload and hosted-image contracts, independent `mediaVersion`, compatibility review, and explicit recovery after an uncertain result. Storage and provider behavior is not simulated in production code.

The additive backend prerequisites are [ADM-06 and ADM-07](../../../backend/docs/admin-product-catalogue.md). Older PATCH clients may omit the timestamp and retain their previous behavior; they do not receive stale-snapshot protection. Their successful catalogue edits still invalidate newer editors' observations. No schema migration, permission expansion or product deletion was introduced. Optional original-request creation recovery remains ADM-08.

## Corrections during verification

The first browser run passed 31 of 34 cases. Two failures exposed one real focus issue: disabling the form before opening review could lose the original trigger. The editor now explicitly restores review-trigger focus when the dialog closes. The remaining failure was an outdated image fixture that did not advance `mediaVersion`; it now matches the real API and asserts the submitted version. Subsequent browser runs passed. The fixture timestamp also now has the API's millisecond precision.

The first real-page helper referred to a nonexistent Prisma `productCategory` model. It was corrected to `category`; that failure occurred before fixture writes. The actual target was checked again before the successful run. Runtime output included Node experimental Web Crypto and PostgreSQL query-queue deprecation warnings; no browser page error occurred.

Visual review tightened category pagination spacing, aligned editor actions, reduced excess checkbox spacing and added complete catalogue-footer padding. An additional 375px Axe scan exposed transient low contrast while an enabled button's background was still animating from disabled grey. Product-page buttons now change colour immediately while retaining their shadow/transform treatment. No Axe rule or assertion was removed.
