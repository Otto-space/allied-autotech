# Service detail quality milestone

Route: `/services/[serviceId]`

Status: complete; local acceptance passed, 30 September 2026.

Scope: fixed-price and quotation-required service detail, including the forms embedded on this route. The separate Booking and Quotation milestones remain outstanding.

## Audit and design

Baseline captures at 390, 768, 1280 and 1440px showed a long undifferentiated page, native branch and vehicle selectors, weak form boundaries and generic breadcrumbs. The existing API integration, customer identity checks and uncertain-submission protections were retained.

The [three concepts](service-detail-concepts/README.md) were generated and inspected before implementation. The result uses a compact split overview with Nippo heading, exact API price and duration, an explicit media fallback, readable service breadcrumbs, open service context and a bordered request panel. Quicksand, visible control borders, compact icons, 44px controls and restrained ink/red/navy styling follow the accepted direction. On mobile the form precedes supporting context. There are no password inputs on this route.

Generated media and example identities are not production records. Existing shared navigation and the authentic wordmark supersede the concepts' approximate headers. The implementation uses no invented wizard, service taxonomy, branches, price, availability, response-time promise or workshop photograph.

## Contracts and behavior

Read-only review covered service-operation routes, schemas, service, repository and policy; public support routes and schemas; and the current frontend DTOs, public loader, session/mutation hooks and account-detail loaders. Paths below omit `/api/v1`.

| Endpoint                                                                 | Used behavior                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /public/services/{serviceId}`                                       | UUID and returned-identity validation, actual service title, description, pricing type, duration and authorized public image. Server rendering and metadata share a cached request; the browser does not duplicate the initial detail read.                       |
| `GET /public/booking-policy`                                             | Current version, booking window, cancellation/deposit terms and rescheduling rules. The current owner policy requires no deposit. Policy failure blocks a new booking request.                                                                                    |
| `GET /public/branches?limit=20&cursor=…`                                 | Searchable current-page branch choices and bounded cursor navigation. The UI does not claim catalogue-wide search.                                                                                                                                                |
| `GET /public/services/{serviceId}/slots?branchId=…&limit=50&cursor=…`    | Available slot choices in Lagos time. The client rejects mismatched branch/service identities and invalid intervals. Empty/error/loading states and further-page controls remain available.                                                                       |
| `GET /auth/session`, `GET /customers/profile`, `GET /customers/vehicles` | Optional signed-in account check; customer-only saved details; returned-profile identity verification; paginated vehicle choices; partial-read retry. No anonymous customer-record request is made.                                                               |
| `POST /customers/bookings`                                               | Customer session, CSRF and idempotency key; selected slot, policy version, optional owned vehicle and normalized notes of at most 2,000 characters. The server owns availability and approval. A receipt with `REQUESTED` is explicitly awaiting workshop review. |
| `POST /public/support/enquiries`                                         | Actual `SERVICE` enquiry with service ID, handling branch, contact fields, subject and message. Review precedes submission; accepted receipt does not create a formal quotation or confirmed appointment.                                                         |

An uncertain booking locks its original fields and retries the same body/key. A session change aborts pending client operations, clears personal selections and receipts, and preserves an account-recovery notice even if the public service reload fails. An uncertain anonymous enquiry remains locked through a service remount or account change. A preflight session failure cannot unlock an already uncertain booking.

Primary-record failures retain real 404/500 status and readable recovery pages. No whole-route loading boundary turns missing records into streamed 200 responses. Public indexable details receive identity-derived Service and BreadcrumbList structured data with the CSP nonce. Query/non-indexable variants do not receive that structured data.
