Route `/admin/dispute-policy`, Super Admin only. Baseline production captures at 430/768/1280/1440 pixels and full desktop were inspected; all four had no horizontal overflow or page errors. The current route renders `OperationalPolicy kind="DISPUTES"`. Its shared form/history serves retention as well. Use a dedicated page without redesigning retention. Reuse existing policy contact search, form normalization, weekday labels, validation, confirmation dialog, feedback and hardened approval/recovery patterns. ## Contracts and permissions

- Existing GET `/admin/policies?key=disputes&limit=100` returns descending bounded history, not an independently selected current policy. Add private GET `/admin/policies/disputes/current` with server evaluatedAt/current/latest/nextScheduled/history, current actor/session checks, consistent snapshot and minimal atomic READ audit. Reuse bounded database-aborted read retry to tolerate authenticated session touches.
- Existing POST `/admin/policies` with kind DISPUTES requires Super Admin/MFA/CSRF. expectedVersion is nonnegative, source 10–500 trimmed characters, evidence 20–1000, effectiveAt ISO. Publication refuses stale versions and backdating beyond the existing tolerance, records immutable APPROVED/Q9 provenance and an atomic CREATE audit.
- Settings require different primary/backup account UUIDs, 1–7 day numbers 0–6, opening minute 0–1438, closing minute 1–1439 with opening before closing, and at most 100 ISO holiday dates. Calendar confirmation is an explicit UI condition, not an extra request setting. Deduplicate/sort holidays and preserve weekday semantics.
- Contacts must be active, verified Staff/Admin/Super Admin accounts, each with active DISPUTE_MANAGE. Existing source: GET `/admin/staff?status=ACTIVE&limit=50`, supported q 2–100 and UUID cursor; current account GET `/admin/staff/:id`; GET `/admin/capabilities?userId=:id&activeOnly=true` returns all active grants and performs current actor checks/private audited reads. Keep selections across search/pages and show full names/emails below narrow selects. Do not assume a role alone grants dispute authority.
- Publication currently lacks the complaint path's fresh transaction actor lock. Extend the lock to DISPUTES, lock the two contact accounts in stable UUID order, then run existing active/verified/role/grant/version checks. Capability changes share the organization access lock. No schema/migration is needed.
- The current operational-alert worker reads the effective disputes policy. For an unresolved dispute missing acknowledgementDueAt, it calculates the end of the applicable approved working day and supplies default primary/backup contacts when primary is absent. Publishing itself does not mutate individual disputes, submit evidence or resolve a case. Provider response deadlines remain authoritative. Do not claim all existing assignments are automatically replaced or that every missing backup is repaired. Worker/provider behavior is outside this page redesign.
- Own profile GET `/staff/profile` gates current identity. Contact-specific 404 is a selection conflict, not proof that the acting user's entire session is revoked. Permission/session loss clears private facts; transient failures preserve stale facts/drafts and block publication.
