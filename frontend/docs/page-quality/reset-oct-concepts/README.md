# Reset-password concepts

Fresh desktop, manual-entry mobile and completed/invalid/uncertain state concepts were generated on 8 October after four baseline captures and before production edits.

Retain the accepted Login/Registration/Recovery system: existing approved photograph, actual Brand, Nippo editorial heading, Quicksand UI, 46/54 desktop split and 440px desktop form. Below 900px omit decorative imagery. Use 48px inputs/actions, 44px reveal/navigation/disclosure controls, clear cool-grey borders and red focus. Default content should fit the tested mobile height; allow vertical scrolling on short screens, enlarged text and expanded/error states. Never hide horizontal overflow to disguise a broken layout.

The normal email-link view collapses the masked Recovery token disclosure; manual entry remains available and expanded without a usable fragment. Preserve the concept's primary heading, labels, hints, actions and state copy. Use the real Home / Reset password breadcrumb rather than the generated slash/back-arrow or icon-only Home variant. Ignore invented state-board logos/taglines and placeholder passwords. State panels are references, not enclosing production cards. Help remains the existing account-security link.

Tokens and passwords are never published, drafted or automatically submitted. Missing/bad fragments do not imply server validation; users can open the newest recovery email, request a link or paste a token. Only a validated API receipt establishes completion. A lost response leads to sign-in/new-link guidance rather than a blind retry of a potentially consumed token. Reveal controls are independent and re-mask on sensitive transitions.
