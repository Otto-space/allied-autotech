# Managed workforce enquiries — milestone 107 specification

Route `/admin/workforce/enquiries` is the single active page after milestone 106 local acceptance. Prior goal turn: progress. Audit and four native baselines were completed on 19 October 2026 before runtime changes.

## Audit and authoritative boundaries

The generic queue currently renders a full reply form and, for sales supervisors, an assignment form in every large record. It has only in-memory forward paging, raw status text, no search, no named branch/assignee, no conversation history and no fresh selected-record read. Refresh can retain facts on failure. Its uncertain-result boolean can be cleared without independent reconciliation. Four baselines at 430/768/1280/1440px have no overflow/page errors but show repetitive oversized forms, especially on mobile.

Current managed scope: Customer Service reads all enquiry types in its branches; Sales Supervisor reads product/vehicle enquiries in its branches; Sales Cashier reads assigned product/vehicle enquiries in its branches. Only ENQUIRIES_ASSIGN branches permit sales reassignment. Existing replies are customer-visible and reject RESOLVED/CLOSED or stale versions. Assignment checks current eligible sales access in the record branch. Preserve these boundaries and the current MFA/CSRF/actor/workforce transaction protections.

Existing APIs: collection GET, enquiry reply POST, assignment PATCH, and GET eligible assignees. Existing assignee options silently cap at 100 and have no query support. Add compatible searchable pagination rather than pretending this is a complete directory. No existing managed enquiry detail/history endpoint is available. Do not use legacy support endpoints blocked by the workforce boundary.
