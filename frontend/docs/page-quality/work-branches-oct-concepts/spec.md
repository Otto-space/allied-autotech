# Branch workspace specification

Keep the existing Allied dashboard shell and Quicksand. Pale gray canvas, restrained white editor, ink text, red primary/selection accents, thin visible blue-gray borders,6px corner radii. Heading30px desktop/24px mobile, body14px, controls48px and minimum44px touch targets. No images, maps, metrics, avatars, deletion or invented hours.

Default view: semantic Overview / Branches breadcrumb, concise heading/description, Add branch action, compact name/code/city/state search plus active-status filter/refresh, loaded-page count, ruled branch records with name/code/location/status and useful actual contact facts, then pagination. Search and filters operate server-side and reset cursors. URL preserves q/isActive/cursor/history and selected branch or creation mode; invalid parameters show an actionable error without private list requests.

Selected/editing view: roughly38% list and62% editor on wide screens; selection has a subtle background and red leading rule. At narrow widths collapse the list/filter area behind Back to branch list while editor is open. Closing restores the same filter/page. Selected branch is fetched directly, not inferred from current page membership. Form groups are Branch identity, Location, Public contact and Active status. Pair fields on desktop; stack at small mobile widths. Country remains Nigeria; timezone is editable validated IANA text. Review displays all changed facts with human labels and explicit clearing of optional contacts.

Creation uses the same editor with blank supported fields and existing defaults. Creation begins only through Add branch. Neither creation nor editing asks for a password because the existing branch contract does not require one. Deactivation guidance explains the actual active-staff restriction. Full IDs/timestamps live in a Branch record disclosure. Fields retain safe drafts after rejected saves; a changed target requires explicit reload before a new review.

Reuse own-profile/current-role checks, useResource, API/CSRF client, MutationReview, existing cursor URL helper, form/draft infrastructure and business-date formatting. Minimal actor-bound recovery metadata must survive reload. Store no full contact/address/request body in recovery markers. A pending create retains only its public branch code and can be checked through an exact-code query, but current records do not prove the original request outcome. Reconciliation requires an independent audit/admin review and acknowledgement; no automatic retry.

Acceptance: actual isolated API create/edit/status/stale/concurrency/ownership/actor checks and old public/branch-picker contracts; production browser search/selection/history/forms/validation/errors/drafts/recovery/roles; responsive/Axe320–1920; native four-width concept comparison; meaningful type/lint/build checks; connected browser/API/database preservation evidence. Complete this route before another route.
