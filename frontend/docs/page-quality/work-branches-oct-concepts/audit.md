# Branch management audit

Route `/admin/branches`, milestone91 in progress after accepted milestone90. The route already works through `app/admin/[resource]/page.tsx` and the shared `AdminResourcePanel`; there is no dedicated branch component yet. Existing navigation already exposes it to Admin and Super Admin. Enrolled administrators retain the existing workforce/legacy boundary.

Four baseline captures at430/768/1280/1440 were inspected natively before runtime changes. No page-level overflow or page errors occurred, but at430 the table clips its action column inside a horizontal region. Branch contact/location facts are absent from the list; filters/search are missing; create form occupies the page even when unused; field grouping is generic; selection/cursors disappear on reload; the breadcrumb uses text slashes. Unknown saves are locked only in component memory and mutation receipts validate only the ID.

The existing authenticated API supports Admin/Super Admin list, single-record GET, POST creation and PATCH editing. Listing uses ascending UUID cursors and optional `isActive`; detail/list reads have minimal atomic READ audits. Safe fields are id/code/name/phone/email/address/city/state/country/timezone/isActive/createdAt/updatedAt. Public branch endpoints expose only active records.

Creation/update validation: uppercase2–20 character code matching letters/digits/hyphen, name1–120, address1–250, city/state1–100, country Nigeria, valid IANA timezone, nullable optional phone7–32 and email≤254. Creation defaults active/Nigeria/Africa-Lagos. Updates are partial and nonempty. CSRF, verified privileged session and backend authorization remain authoritative. Deactivation takes the branch advisory lock and rejects any active Staff user assigned to that branch. There is no delete operation or opening-hours/map/staff-count contract.

Required compatible backend work: bounded literal case-insensitive search over name/code/city/state; explicit private/no-store branch administration responses; current actor recheck under lock; optional timestamp revision guard under branch lock for stale edits; actual OpenAPI response schemas. No database schema/migration is needed. Preserve existing branches, public DTOs, assignment/deactivation lock ordering and old clients that omit the revision field.

Required frontend work: dedicated list/editor workspace, URL-backed filters/paging/selection, direct detail fetch beyond current page, grouped validated fields, full operation review, exact receipts, current actor/record preflight, stale-draft handling, persistent uncertain-outcome lock and explicit fresh-inspection/independent reconciliation. Creation recovery must never resend automatically or assume a matching code proves the original request succeeded.
