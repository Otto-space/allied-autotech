# Workshop booking detail

Date: 12 October 2026. Route: `/admin/bookings/[bookingId]`. Gate 50 is locally accepted after final production verification and concept comparison. The application-wide goal remains active.

## Audit and design

The previous page stacked narrow forms below a widely spaced summary, used a generic slash-separated detail breadcrumb, and always displayed deposit fields. A staff member could see progress and work-order actions for another assignee even though the backend rejected those writes. Background failures were not disclosed and manual failures could leave the previous record visible.

Three [fresh desktop, mobile/state and record/editor concepts](work-booking-detail-oct-concepts/README.md) preceded production changes. The implementation keeps the real shell and Quicksand, adds an ink service/status summary, ruled facts and notes, compact paired assignment/progress forms, section anchors, a disruption disclosure and responsive quotation/work-order records. The full historical deposit record remains available when present. No deposit requirement is introduced.

## Behavior and boundaries

- Uses existing booking detail, assignment, status, disruption, quotation and work-order endpoints. Expected booking/work-order versions and quotation revisions, CSRF, review confirmation and server pricing remain authoritative. Review cancellation sends no booking mutation. Rejected or uncertain proposals cannot be replayed within the same dialog; closing refreshes the record.
- Entity breadcrumbs show the actual service name, with ordered-list semantics, chevrons and a current-page marker. The shell's generic breadcrumb is suppressed only for this detail route. Full references remain in the record/review, not the breadcrumb title.
- STAFF uses its own branch profile for assignment. Other status changes, disruption, quotation changes and work-order edits require current assignment; ADMIN/SUPER_ADMIN retain existing access. Confirmation separately requires BOOKING_CONFIRM and a people/equipment review, including for unassigned staff within the same branch. Quotation authoring still requires a staff profile.
- Private read failures hide records; background failures retain data with a stale notice and block changes. Access failures hide privileged forms. Session changes unmount the record and review. A mismatched returned booking identifier fails closed. Existing backend branch, active-profile and concurrency checks remain the final authority.
- Inputs retain original validation limits and safe errors. Cancellation/resource-review errors are connected to their fields and focus the invalid control. Quotations and work orders reuse existing editors and server-calculated amounts; mobile line items preserve all five labelled values.
