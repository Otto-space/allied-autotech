# Customer inspection history concepts

Prepared before production implementation on 9 October 2026 using built-in ImageGen. Accepted [desktop](desktop.webp) and [mobile, report and recovery states](mobile-states.webp) guide this route. Original PNGs remain under Codex generated_images. A first mobile proposal was rejected for rainbow statuses and large red detail buttons; the retained correction replaces those with neutral statuses and compact disclosure actions.

## Implementation specification

Keep the actual Allied dashboard shell, logo, page search, role navigation and support controls. Quicksand throughout the private workspace; heading 30px desktop/27px mobile, section titles 18px, body/labels 13–14px, selects 16px/48px high, actions at least 44px. Ink #01121A, red #E60301, cool canvas #F4F6F8, white table rows, light guidance #EAF0F5, borders #CBD5DF and select borders #82939F. Controls 6px, outer table 8px; brand focus outline with offset. No photography because this API projects no listing image.

Allowed header copy: Overview / Inspections semantic breadcrumb; Vehicle inspections; Follow your requests, appointment times and inspection reports.; Refresh inspections; Browse vehicles. Guidance: Your inspection appointments / Requested times are preferences. Check the confirmed schedule before you visit. Filters: Inspection status / All statuses, six sentence-case statuses; Rows per page / 10,20,50; Reset filters; All times in Lagos. Count is only N inspections on this page, never a global total.

Desktop table: Vehicle, Appointment, Status, Details. Outline car by actual listing title. Appointment shows Scheduled for confirmed/rescheduled, Last scheduled for completed/cancelled/no-show, or Requested when no scheduled time exists. Requested and confirmed time must remain distinct. Show Awaiting confirmation only for REQUESTED without schedule. Neutral status label; cancellation/no-show may use pale red. View details / Hide details toggles an accessible expanded row below the record without navigating to a nonexistent detail route. Multiple records may be open independently.

Expanded content: preferred time window; customer notes and cancellation reason where supplied; report summary, inspected date, odometer (including zero or Not recorded), condition score (including zero or Not recorded), optional primitive findings; Contact customer care link. Show No inspection report available when absent without implying a report will arrive. Render text as text; no report download/sharing, staff reassignment, direct customer cancel/reschedule or inferred status. Table details adapt to one column without truncating findings or notes.

Below 1100px, render each record as a compact stacked table row with title/status, appointment and disclosure. Preserve table semantics and header associations. At narrow widths keep filters usable with wrapping, then stack if needed; no giant full-width actions. Previous / Page N / Next follows bounded URL cursor history. A direct cursor without history says Later page and offers First page. Status/limit changes reset cursor. API accepts only validated status/limit/cursor; history remains browser-side. Back/Forward/reload preserve filters.

States: skeleton rows while loading; No inspection requests yet with Browse vehicles; No inspections with this status with Reset inspection filters; No inspections on this page with First page; We couldn't load your inspections with safe API copy and Retry inspections. Background failures retain rows with These inspections may be out of date. Refresh before relying on an appointment time. Manual failures hide old rows. Denied/session changes remove private records. Pagination must not continue from stale data. Reduced-motion preferences disable skeleton motion.

## Intentional artwork corrections

Actual shell/logo/search replace generated substitutes. Desktop dictates primary/secondary header actions on every width (omitted by the small state sheet). Requested is the exact status, with Awaiting confirmation separate guidance. Terminal schedules use Last scheduled even where mobile art shortens it. Use ink underlined links, not generated bright-blue text. Use compact Lagos-time ranges: omit the repeated end date only when both endpoints fall on the same Lagos calendar day. Keep the visible All times in Lagos label and explicit timezone on the inspected timestamp. Report preferred dates come from API, not the desktop sample's mismatched date. Page 1 has no invented total. Filter labels sit above bordered fields; full UI controls remain 44/48px even when the concept sheet scales them down. Empty/error views are separate states; never display the artwork's combined error and stale list as one authoritative screen.

Desktop details intentionally group appointment first and report/findings second in two columns, replacing the desktop artwork's three groups. This preserves the mobile concept's appointment-first reading order and gives long report text enough width. Details become a single column below 640px.

## Prompt record

Desktop prompt requested a complete 1536 by 1024 existing-shell history with four rows, the third expanded, filter/pagination controls and real supported report fields. The corrective mobile/state prompt requested neutral statuses, compact ink disclosure actions, readable expanded findings and honest empty/stale/error states. All prompts specified the Allied palette, Quicksand and practical code-native controls, excluding unsupported mutations, photo placeholders and fake totals. WebP conversion changes encoding only.
