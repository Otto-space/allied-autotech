# Workshop appointment slots - local acceptance

Route: `/admin/booking-slots`. Roles: Staff, Admin and Super Admin. Accepted locally on 12 October 2026, the fifty-first expanded milestone. This does not certify the entire application or deployment.

## Design and implementation

Fresh [desktop and mobile/state concepts](work-slots-oct-concepts/spec.md) preceded implementation. The page has an ordered Overview/Appointment slots breadcrumb, compact header actions, applied-filter summary, ink records heading, page-local count, desktop publication rail and labeled mobile records. The existing shell, logo and Quicksand interface typography remain in use.

Status, inclusive Lagos start dates, branch, service and staff filters use the existing `GET /staff/booking-slots` contract. Applied filters and cursor navigation survive reload and browser history. Staff cannot override their branch via the URL. Admin scope choices include inactive records; Staff service choices use the active public catalogue. Dates use a UTC+01:00 start and exclusive next-day upper boundary, without inventing a maximum range. Results follow the backend's ascending appointment-time order. Malformed or mismatched responses fail closed.

Publication retains the existing POST body and server-calculated duration. Staff branch choices use their own branch endpoint and assignment remains restricted to their profile. The existing versioned PATCH and review descriptions remain authoritative. Rejected reviews cannot replay without returning to refreshed data; uncertain publication blocks another submission from the mounted form. Background read failures retain records and drafts while blocking edits. Permission failures hide records; an existing Staff draft stays mounted but disabled until permissions recover. Session/role changes remount the workspace.

## Corrections and evidence boundaries

The first isolated build failed with `ENOSPC`. Automatic approval review rejected cleanup attempts; disk space subsequently became available externally. A later build compiled and completed TypeScript but lacked the standalone packaging completion marker. Its production probe exposed missing CSS/JavaScript, so it was rejected. The final rebuilt artifact passed packaging and asset-load checks.

The first real-data helper used an invalid nested Prisma branch relation. Its setup was corrected to use `branch.connect`, and the audit assertion was aligned with the actual `userId` field. The complete corrected run passed; application rules were not weakened. The earlier isolated database was unavailable, so verification used a fresh database rather than modifying the application database.

## Changed files and limits

Production: `app/admin/booking-slots/page.tsx`, its new `booking-slots.css`, `app/components/staff-booking-slots.tsx`, new `work-slot-filters.tsx`, optional availability/branch support in `slot-catalog-picker.tsx` and `staff-picker.tsx`, one breadcrumb condition in `dashboard-shell.tsx`, and new `lib/work-slot-query.ts` / `lib/api/work-slot-schema.ts`. QA includes the slot fixture, new browser/query tests, existing slot-test contract updates, concepts and this report.

No backend endpoint, schema or migration changed for this page. Closing a slot does not cancel a booking. Publication does not guarantee customer availability outside booking policy. The create endpoint has no durable original-request key: the UI offers read reconciliation and prevents automatic replay, not a promise of safe POST resubmission. Calendar occupancy and bulk scheduling are not simulated. Deployed role, notification and configuration acceptance remain separate.
