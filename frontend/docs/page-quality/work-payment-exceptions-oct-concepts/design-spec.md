# Payment exceptions design specification

Gate 84. Use Allied ink #01121a, red #e60301, off-white #f4f6f8 and Quicksand. Preserve the existing 256px desktop sidebar and 70px header; mobile shell has an ink masthead and separate search row. At 1440px, content starts at x292 and ends at x1404. Heading 28px; body 14px; labels 12px. Compact spacing, no financial totals.

Header: small FINANCE / EXCEPTIONS eyebrow, Payment exceptions, short investigation scope sentence; Back to operations link. Filters in one restrained horizontal strip with status and type selects and refresh. Queue and workspace use approximately 40/60 columns with a 20px gutter. Queue rows have category, status pill, a two-line summary, Lagos detection time and Open investigation control. Only loaded-page count is shown.

Selected workspace: ink header with Amount mismatch, Open pill and short reference; white content contains original summary, detected/updated pair, current note or honest absence. Action area explains OPEN → INVESTIGATING and requires a 3–2000 character investigation note before review. Closure offers resolved/ignored only from investigating. Prominent review, private source-reference disclosure and safe payment/refund navigation. Closed records replace the form with closure facts. Review dialog repeats current/new state and full note. Unknown outcome has persistent warning and Read current exception action.

At 430px use 16px outer margins and 16px gaps. Filters stack in two compact rows. When selected, workspace precedes the queue; no mobile sidebar or invented widgets. Avoid fixed-height clipping. Reference strings wrap. Minimum 44px controls, visible focus, reduced-motion support, no horizontal page scroll.

Concepts are visual references only. Correct any generated shell, typography, data, count, date, transition or spacing mismatch before implementation. Never import concept pixels as live UI.
