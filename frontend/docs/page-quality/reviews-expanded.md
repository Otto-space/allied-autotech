# Public Reviews — expanded local acceptance

Date: 7 October 2026. Route: `/reviews`. Scope: public reading, discovery, account shortcuts and review guidance, with regression checks of the existing customer submission and administrator moderation workflows. This is a completed local page gate, not whole-application or deployment acceptance.

## Audit and implementation

The previous page used a narrow white column, oversized title, disconnected filter/refresh controls and a customer-only account link visible to every role. It had no submission guidance and little distinction between empty states. The public API was already integrated and authoritative.

Three fresh [concepts](reviews-oct-concepts/README.md) cover the introduction/list, populated review anatomy/FAQ, and mobile page. Implementation retains Nippo/Quicksand, a compact 36px maximum display title, ink statement and guidance panels, a cool-grey feedback band, visible control borders, restrained depth and the existing workshop editorial image. The FAQ explains eligibility, moderation, useful feedback and the separate Customer Care workflow. Existing header/footer and supported navigation are retained.

`ReviewCard` gains an opt-in editorial variant: accessible numeric rating, decorative stars, target label, complete plain-text title/comment and submitted timestamp. Its default dashboard/Home presentation remains intact. No customer names, avatars, overall scores, global totals, private moderation details or new verification claims are fabricated. Counts explicitly describe the current page. Dates preserve the existing Lagos-time formatter.

Filters, reset, refresh and cursor navigation use real bounded public requests. Pending requests are cancelled on query changes; stale responses cannot replace current results. Loading rows are withheld, errors do not masquerade as empty results, and background refresh errors are surfaced. Anchor destinations receive keyboard focus. Native selection and disclosure work without a new UI dependency.

## Authorization and contract

| Viewer                           | Public-page account action                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------- |
| Anonymous                        | Sign in, returning to `/dashboard/reviews`.                                                       |
| Customer                         | Write or check a review in `/dashboard/reviews`.                                                  |
| Staff                            | Read public feedback; customer submission and administrator moderation links are absent.          |
| Admin / Super Admin              | Open `/admin/reviews`; the existing dashboard/API enforce MFA and authorization.                  |
| Unavailable or malformed session | Explain that account options are unavailable and provide retry; public reading remains available. |

The small account component validates the session projection, aborts obsolete checks, and clears/rechecks links on `SESSION_CHANGED`. It does not fetch private review lists. Visibility is UX; backend authorization remains independent.

`GET /public/support/reviews?limit=20` returns approved records ordered by submission date and ID descending, with optional `targetType` and UUID cursor. The page preserves the server seed and its request-scoped metadata deduplication; browser mounting does not duplicate a successful seed read. Existing customer creation and administrator moderation contracts are reused. Product/service/order/vehicle-purchase eligibility still requires a completed, owned source; overall business feedback does not require one. No backend contract or schema change was necessary.
