# Processing jobs baseline and contract audit

Gate93 follows accepted audit logs. Route `/admin/processing-jobs` uses `OperationalJobs`, generic `OperationsQueue`, `OperationActionForm` and `MutationReview`. Navigation lives under Settings; only Admin/Super Admin may read or retry. The verified privileged session and CSRF remain mandatory. Four baseline viewport captures430/768/1280/1440 were inspected natively before runtime edits. They show no overflow or page errors. The local production server had ended before the first attempt; its missing process/handle was verified before restart. A later browser network suspension affected only1440; only that capture was resumed.

Visual weaknesses: a large lead paragraph, generic slash breadcrumb, redundant Back link, generously padded filters, action row and full record sections precede every retry form. On mobile the first form is several screens away. Repeated raw event keys, uppercase status/source labels and UUID-heavy definition lists make the queue difficult to scan. The same source has no total count/search contract. Preserve full facts while moving references and the selected retry to deliberate inspection.

GET `/admin/operations/jobs` accepts optional source OUTBOX/PAYMENT_WEBHOOK, optional status FAILED/DEAD_LETTER/PROCESSING, limit1–100/default25 and a signed80–1024-character opaque cursor. The UI currently requires one source and defaults to OUTBOX. The cursor binds actor/source/status and contains updatedAt/UUID/source; ordering is updatedAt,UUID,source descending. Colliding UUIDs in the two physical tables are valid. Retry/removal of a boundary row does not invalidate the cursor position. Do not lowercase or replace opaque cursors with UUID rules.

Outbox fields include id,eventId,aggregateType/Id,eventType,status,attempts,availableAt,lockedAt,createdAt,updatedAt. Webhook fields include id,eventType,status,processingAttempts,nextAttemptAt,lockedAt,receivedAt,updatedAt. The existing HTTP response also includes nullable raw error fields, which the frontend strips; the new safe current inspection must not expose provider payloads, hashes, secrets or raw diagnostics. Existing nullable diagnostic response keys can remain compatible as null. Each successful list read records a minimal OPERATIONAL_JOBS READ audit, currently in a separate transaction.

POST `/admin/operations/jobs/:source/:jobId/retry` accepts lowercase outbox/webhook, UUID, expectedAttempts0–1000 and trimmed reason3–500. Only FAILED/DEAD_LETTER with matching attempts can change. Outbox becomes PENDING; webhook becomes RECEIVED. Locks/errors clear, scheduling advances, attempts/idempotency keys remain. Notification-delivery outbox events atomically reset the matching undelivered failed/dead-letter delivery; missing/active/completed/mismatched delivery returns409 and rolls back. STATUS_CHANGE audit and queue changes are atomic. Processing jobs never offer retry. Queue acceptance proves neither delivery nor financial settlement. Preserve worker/provider checks and manual webhook retry behavior after the automatic attempt budget.

Gaps: no direct current-job read across all states; no service-level current actor/session lock for jobs/retry; no optional inspected revision condition; uncertain UI locks are memory-only and disappear on reload; retry receipts are shape-validated without exact target/source/attempt matching. Fix these without a schema change. Add safe audited current inspection, optional expectedUpdatedAt comparison, transaction-bound current identity, persistent minimal pending markers and exact response checks. Durable original-request receipts remain a separate optional capability; current inspection must never claim the original outcome.

Existing useful tests: operations.spec.ts retry/validation/stale-attempt/MFA/Staff/unknown-response scenarios; operational-job-page units; signed-cursor backend units; notification-retry, webhook-claim-ownership and pagination integration tests. The old pagination suite retires matching synthetic jobs globally and deletes its fixtures, so do not run it against the retained shared test fixture database. Adapt focused tests to owned retained fixtures with full original-row hashes. Legacy direct-service retry tests use fabricated session IDs and need truthful sessions when current-access validation is added.

No database write or runtime implementation for gate93 has occurred at this design checkpoint. Browser-plugin capability is absent; Playwright/Edge is the recorded fallback.
