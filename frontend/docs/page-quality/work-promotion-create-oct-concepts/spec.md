# Promotion creation — implementation specification

Inspected before UI edits. Built-in Image Gen, `ui-mockup`, two fresh concepts: desktop 1435 × 1096, mobile 786 × 2001. Source prompts requested the established Allied workspace, cool grey canvas, white grouped form, Quicksand, visible input borders, four numbered sections, red review action, disabled default and a narrow guidance rail. Concepts are design references, never shipped as UI.

- Preserve the existing authenticated shell, full navigation, branch context and actual brand asset. The shortened generated sidebar and account menu are illustrative; do not remove existing navigation to match it.
- Above-fold allowed copy: Promotions / Create promotion; Create promotion; Set the offer, schedule and limits before reviewing.; Back to promotions; Promotion settings; Offer details; Promotion name; Redemption code (optional); Description (optional); Discount; Discount type; Discount percentage (or Fixed discount (NGN)); Minimum subtotal (NGN, optional); Discount cap (NGN, optional); Before you save; Review first; Review the exact amounts, dates and limits before creating this promotion.; Customer redemption; A code is required for customer redemption.; Existing orders; Existing order discounts stay unchanged. Existing contract labels are intentionally retained where the generated concept shortened them.
- Continue with Schedule, Starts at (Lagos time), Ends at (Lagos time), All dates use Lagos time (UTC+1).; Usage and availability; Total usage limit (optional); Per-customer limit (optional); Enable this promotion; New promotions start disabled.; Review promotion.
- White form, cool neutral #f5f6f7 surroundings, ink #01121A, red #E60301 primary, muted text #50616c, border #8998a3, 8px control corners, 12px outer corners and subtle shadow. No gradients or hero/media assets.
- Use Quicksand throughout; heading 24–28px, section headings 16px, labels and controls 13px, body 14px. Deliberate 44px control height, visible red focus ring, readable invalid/disabled states. Existing SVG/lucide icons at 16–20px, stroke 1.75–2; ChevronRight/ArrowLeft navigation, ClipboardList/Tag/Layers guidance. Numbered headings use red numerals, no decorative icon tiles.
- Desktop: open header with secondary back link, form plus 240–260px guidance rail, form two-column field grids. Description spans full width. Four sections separated by rules. Guidance uses three open rows, with a short white surface rather than stretching to the bottom of the form.
- At narrow workspace widths the rail moves below; at <=900px viewport single-column fields and non-sticky guidance. Dates also stack, intentionally differing from the mobile concept's cramped pair. Full-width review action on mobile. Default optional inputs remain empty; generated `0` placeholders are not submitted values. Do not invent placeholders or percentage/currency suffix adornments.
- Preserve all validators, millisecond Lagos date conversion, exact kobo arithmetic, nullable limits, conditional discount clearing, explicit review before save and disabled initial configuration. Explain code-less redemption, zero discount/cap, blank limits and checkout eligibility beneath the relevant fields.
- Required downstream states extend this system: review dialog with every submitted fact, busy/double-click protection, rejection, durable uncertain-save notice, read-only receipt check, original-request review/retry, confirmed created/recovered link, expired/corrupt/storage-unavailable lock and denied roles. Never infer saved identity from name/code searches or automatically replay on reload.
- Separate creation component owns recovery and session checks. Reuse PromotionForm with an opt-in grouped layout; existing detail editor keeps its existing layout and behavior until its own gate. Reuse MutationReview, feedback, money/date formatters, account session and API client. Backend receipt and audit commit atomically using the existing IdempotencyRecord model; no schema change.
- Fidelity QA must compare both saved concepts with final screenshots in the same pass, native-size captures plus required practical viewport widths, copy diff and at least five concrete comparisons. Functional checks cannot replace visual checks.
