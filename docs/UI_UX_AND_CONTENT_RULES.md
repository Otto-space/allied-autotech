# UI, UX and customer language

Extend the existing shared colour, spacing, radius, elevation and focus tokens.
Give each screen a clear hierarchy and each stage one primary action. Preserve
working interfaces, real data, material faults, pricing conditions and permissions.

Use responsive layouts, persistent labels, comfortable targets, native semantics,
visible keyboard focus and selected states that do not depend on colour. Check
loading, empty, pending, disabled, validation, failure, retry and success states.
Forms must preserve useful input, prevent duplicate effects and explain recovery.
Test modal focus, scrolling, fixed layers, narrow screens and reduced motion.

Use familiar words in customer screens, notifications, email and Allie replies.
Keep hints short and place essential help beside the action. Explain the actual
outcome: an unknown payment is being checked, not necessarily failed; a booking
request is not a confirmed appointment. Keep unknown facts visibly unknown.
Technical terms remain appropriate in developer documentation.

Choose photographic containers and focal points for authentic source assets.
Content photos should fill intended containers without stretching or accidental
gaps; preserve the subject and use an appropriate source ratio. Logos and exact
diagrams need non-cropping treatment. Never fabricate inventory photography.

Verify changed journeys with relevant tests and rendered evidence, then review
the final diff for regressions, security and data integrity. Follow the existing
continuous quality directive and quality register; do not create a second backlog.
