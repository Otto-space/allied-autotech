# W11: independent grants within managed workforce access

Source: `feat/workforce-independent-access-20261027`, based on W10 `11c4ac15`,
reusing the authoritative restoration checkout. No deployment or new worktree.

## Reproduction and policy contract

A newly created isolated Accountant with an explicit REFUND_APPROVE grant passed
the existing refund service's stage-scoped policy, but the same authenticated HTTP
queue returned 403 at the managed boundary. Equivalent independently guarded
dispute, privacy and financial-policy workflows were also blocked. No production
accounts or grant prevalence were inspected.

The native fixture first failed the expected 200 contract, missing independent
projection, and managed-Admin inspection restriction. Later fixture refinements
were rejected by payment-target, verified-capture and online-reference database
constraints; the fixtures were corrected without changing those safeguards.

The precedence model for this bounded batch is:

1. Current account status, verification, session and MFA restrictions remain first.
2. The protected owner and unenrolled legacy account policies retain their existing
   domain baselines. Enrollment deliberately restricts broad legacy operational
   access, including for Admin. Position, availability and a copied URL grant nothing.
3. Pinned active responsibility definitions supply only their existing branch or
   assigned-record actions. Independent grants never widen those scopes.
4. Recognised active `UserCapability` rows supply their separately controlled duty.
   The current seven names are reused, with owner-only grant/revoke administration.
   This is not permission to delegate a duty or bypass domain eligibility.
5. Existing record, stage, assignment, approval separation, upload, CSRF, concurrency
   and recovery checks remain authoritative. Removing one source retains another
   legitimate source; unknown or revoked independent values supply no access.

Refund grants retain the existing company/stage policy. A managed Admin's current
refund inspection now follows that stage policy instead of restoring its old broad
Admin exception. Dispute Staff remain primary/backup-only; an explicitly granted
Admin retains the existing supervisory dispute policy. Privacy and financial-policy
duties retain their existing domain scope and safeguards. No blanket role bypass
or unrestricted capability union was introduced.

## Implementation

- The existing seven-name owner-grant catalogue is shared by request validation
  and the compatibility boundary. Exact existing endpoint shapes and verbs require
  a current grant before reaching the existing domain services.
- Current access returns a separate recognised `independentCapabilities` array;
  the responsibility permission/scope arrays remain unchanged. Opaque revision and
  learning eligibility keys include it, so revocation affects the same session.
- Management inspection shows this separate grant summary only to the owner.
  Delegated responsibility operators receive no independent grant names. Assignment
  impact fingerprints include the owner-visible independent snapshot while keeping
  the existing responsibility-only change contract truthful.
- The maintained UI registry supplies independent work links, page guards and
  overview links. Existing refund/dispute/privacy/financial-policy pages are reused.
  The shared refund page uses its scoped queue for managed Admin; legacy payment
  shortcuts and the unavailable broad dispute overview are omitted in managed mode.
- Refresh/removal unmounts protected content, aborts and discards old independent
  reads, clears protected drafts and redacts uncertain recovery details without
  resubmitting actions. Notification refund/dispute targets use actual current
  domain scope; a grant revocation removes the target.
- Four backend-only reviewed help articles follow explicit independent grants.
  `work-access` advances to v5. A model cannot infer a grant from position, read
  private records, assign operators or execute a refund. Default AI flags stay off.
