# Efficient delivery and verification

Record a start time and target each bounded work package for completion within
60 minutes, reserving time for verification. During initial inspection, identify
when the full goal exceeds that window and split it into complete, testable
packages without dropping requirements. At the hour boundary report the verified
outcome, unfinished scope and exact blocker or next package. Leave recoverable
work; never interrupt a critical data operation to meet the clock.

Inspect existing architecture and scripts once, then use targeted searches. Batch
independent reads and checks; keep dependent changes sequential. Reuse verified
dependencies, shared primitives and existing payment, booking and support systems.
Do not delegate by default, add speculative abstractions or repeat settled
reference research. Research unresolved provider details from official sources.

Keep one requirement ledger: requirement, evidence, changed location, verification
and status. Use verified, implemented-but-unverified and blocked accurately. Run
focused checks while editing and required project gates at completion. Repeat
checks only after relevant changes, failures or unresolved concerns. Never weaken
assertions, hide failures or claim a measured saving without evidence.

Preserve disk reserve, database isolation, authentication, permissions and business
policy. Use isolated tests and distinguish mocked, provider test-mode and live
evidence. No real charges, customer messages, merchant changes or production
publication without current authorisation. Keep secrets out of chat, source and
logs. State exact remaining credentials, account setup and implementation work;
do not say only a key remains while other prerequisites are unverified.

Review the final diff and report working outcomes, actual checks, migrations,
activation steps and remaining limits concisely. These rules guide agent decisions;
they are not an automatic security or quality guarantee.
